# Webpack Project – Setup Notes

## Quick start checklist (new project)

1. GitHub: new **public** repo, README, `.gitignore` template **Node**
2. `git clone <repo-url>` → `cd <repo>` → `code .`
3. `npm init -y --init-type=module`
4. `npm install --save-dev webpack webpack-cli webpack-dev-server html-webpack-plugin style-loader css-loader`
5. Create `webpack.config.js`
6. `mkdir src` → `New-Item src/index.js, src/template.html, src/styles.css`
7. `npx webpack serve` → http://localhost:8080
8. Deploy: see section 9

---

## 1. Repository

- One repo per project that uses npm/webpack (own `package.json`, own `node_modules`, own GitHub Pages).
- GitHub Pages = one site per repo. Deploying to `gh-pages` would break other projects served from `main` in a shared repo.
- Plain HTML/CSS/JS projects without a build step can live together in one repo.
- Repo must be **Public** for free GitHub Pages.
- Node `.gitignore` template already ignores:
  - `node_modules/` – downloaded packages, huge, recreated anytime with `npm install`
  - `dist/` – webpack output, generated by `npx webpack`
- Rule: commit what I write, don't commit what can be generated.
- Always check the terminal path before running npm commands (must be `...\<project>>`).
- Commit after every finished step.

## 2. package.json

```
npm init -y --init-type=module
```

- `npm init` creates `package.json` (the project's "shopping list": name, dependencies, scripts).
- `-y` accepts all default answers (can be edited in the file later).
- `--init-type=module` adds `"type": "module"` → I can use `import` / `export` (also in `webpack.config.js`).
- `scripts` = shortcuts for commands (`npm run <name>`).
- Extra fields `repository`, `bugs`, `homepage` are added automatically when the folder is a GitHub repo.

## 3. Installing packages

```
npm install --save-dev webpack webpack-cli webpack-dev-server html-webpack-plugin style-loader css-loader
```

- `--save-dev` → `devDependencies` – tools only for development/build, not shipped to the browser.
- Install locally (in the project), not globally (`-g`) – the project must work from its own `package.json`.
- `npx <tool>` runs a tool installed in the project's `node_modules`.
- Creates `node_modules/` (never commit) and `package-lock.json` (commit – exact installed versions).
- `^5.6.0` = newer versions allowed as long as the first number stays the same.
- Hundreds of packages get installed because my packages depend on other packages.
- `npm warn deprecated ...` = old sub-packages, usually harmless.

| Package                  | What it does                                                         |
| ------------------------ | -------------------------------------------------------------------- |
| webpack                  | bundles JS modules, CSS, images into `dist/`                         |
| webpack-cli              | lets me run webpack from the terminal (`npx webpack`)                |
| webpack-dev-server       | local server at `localhost:8080`, auto-refresh on save               |
| html-webpack-plugin      | builds `dist/index.html` from my template and injects the `<script>` |
| css-loader               | lets webpack understand `import "./styles.css"`                      |
| style-loader             | injects that CSS into the page as a `<style>` tag                    |
| html-loader _(optional)_ | only needed for local images referenced in HTML (`<img src="...">`)  |

- Before committing, `git status` must NOT show `node_modules/`.

## 4. webpack.config.js

```js
// webpack.config.js
import path from "node:path";
import HtmlWebpackPlugin from "html-webpack-plugin";

export default {
  mode: "development",
  entry: "./src/index.js",
  output: {
    filename: "main.js",
    path: path.resolve(import.meta.dirname, "dist"),
    clean: true,
  },
  devtool: "eval-source-map",
  devServer: {
    watchFiles: ["./src/template.html"],
  },
  plugins: [
    new HtmlWebpackPlugin({
      template: "./src/template.html",
    }),
  ],
  module: {
    rules: [
      {
        test: /\.css$/i,
        use: ["style-loader", "css-loader"],
      },
      {
        test: /\.(png|svg|jpg|jpeg|gif)$/i,
        type: "asset/resource",
      },
    ],
  },
};
```

| Option                                | Meaning                                                                                    |
| ------------------------------------- | ------------------------------------------------------------------------------------------ |
| `import path from "node:path"`        | built-in Node module for file paths                                                        |
| `export default { ... }`              | the config object webpack reads                                                            |
| `mode: "development"`                 | readable output, fast build                                                                |
| `entry: "./src/index.js"`             | starting point – webpack follows all imports from here (dependency graph)                  |
| `output.filename` / `output.path`     | result goes to `dist/main.js`; `path.resolve(import.meta.dirname, "dist")` = absolute path |
| `output.clean: true`                  | empties `dist` before every build                                                          |
| `devtool: "eval-source-map"`          | errors in browser console point to my original files/lines                                 |
| `devServer.watchFiles`                | dev server also reloads on `template.html` changes (it doesn't by default)                 |
| `new HtmlWebpackPlugin({ template })` | builds `dist/index.html` from my template and injects `<script>`                           |
| `module.rules`                        | what to do with non-JS files; `test` = regex for file extension                            |
| CSS rule                              | loaders run right to left → `css-loader` must be last                                      |
| Image rule                            | `asset/resource` – images imported in JS get copied to `dist`, import gives the final path |

- `HtmlWebpackPlugin` is a class → needs `new`.
- File name must be exactly `webpack.config.js`.
- After changing the config, restart `npx webpack serve` (Ctrl+C, run again).
- If using `html-loader`, add a rule: `{ test: /\.html$/i, use: ["html-loader"] }`.

## 5. PowerShell (instead of Linux commands from tutorials)

- No `touch`. Create files/folders with:
  ```
  mkdir src
  New-Item src/index.js, src/template.html, src/styles.css
  ```
  (`ni` = short alias for `New-Item`; errors if the file already exists – harmless)
- Old Windows PowerShell doesn't support `&&` → run commands one by one.
- `ls -Force` shows hidden files (e.g. `.gitignore`).
- `LF will be replaced by CRLF` warning from git = line-ending conversion, harmless.

## 6. src files + dev server

- `template.html`: do NOT add `<script>` (HtmlWebpackPlugin injects it) or `<link rel="stylesheet">` (CSS comes via JS import).
- `index.js` must `import "./styles.css";` (side-effect import).
- Run dev server:
  ```
  npx webpack serve
  ```
  → http://localhost:8080, auto-reload on save. Builds in memory – does NOT create `dist/`.
- Server blocks the terminal → open a second terminal (+) for git. Stop server with Ctrl+C.
- Keep the dev server running while styling – CSS reloads on save.

## 7. Modules & images with webpack

- Webpack bundles only files reachable through `import` from `entry` (`src/index.js`).
- A new file does nothing until it's imported (directly or through another imported file).
- Images go to `src/images/`, file names lowercase, no spaces/diacritics (GitHub Pages server is case-sensitive).
- Images used in JS must be imported:
  ```js
  import restaurantImage from "./images/restaurant.jpg";
  img.src = restaurantImage; // final path generated by webpack
  ```
- A string path (`img.src = "./images/x.jpg"`) breaks after bundling.
- Local images directly in HTML need `html-loader`.
- Webpack renames images with a content hash (cache busting).
- Free photos: Unsplash, Pexels (credit the author).

## 8. Debugging & tools

- Errors show in the browser as an overlay + in F12 → Console (with `eval-source-map` they point to my original file/line).
- Ctrl+U (page source) = HTML from the server; F12 → Elements = live DOM after JS ran.
- F12 → Elements → Styles: edit CSS live in the browser to try values, then copy working ones to `styles.css` (browser changes are lost on reload).
- F12 → Elements → Computed → Rendered Fonts: shows which font is actually used.
- VS Code: F2 on a variable = rename all its uses (scope-aware, safer than find & replace).
- VS Code: Ctrl+H = find & replace (needed for class names in strings and CSS).
- Renaming only letter case on Windows: `git mv old.md NEW.md` (VS Code rename isn't detected by git).

## 9. Deploy to GitHub Pages

- GitHub Pages serves `index.html` from the repo root, but mine is in `dist/` → push only the contents of `dist` to a separate `gh-pages` branch.
- `main` = source code, `gh-pages` = built site only. Never code on `gh-pages`.
- Never create a pull request from `gh-pages` (GitHub offers it after first push – ignore).

First time only:

```
git branch gh-pages
```

GitHub → Settings → Pages → Deploy from a branch → `gh-pages` / root → Save.

Every deploy (run one by one):

```
git status                        # must be clean
git checkout gh-pages
git merge main --no-edit          # bring latest code
npx webpack                       # build into dist/
git add dist -f                   # -f: dist is in .gitignore
git commit -m "Deployment commit"
git subtree push --prefix dist origin gh-pages   # push only dist contents
git checkout main                 # go back!
```

- Live URL: `https://<username>.github.io/<repo-name>/` (1–2 min delay, see Actions tab).
- Add the live link to `README.md`.
- `git status` first line shows the current branch – check it before coding.
