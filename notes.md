# Restaurant Page – Notes

## 1. Repository

- Create repo on GitHub: **Public** (needed for free GitHub Pages), add README, `.gitignore` template **Node**.
- Node `.gitignore` already ignores:
  - `node_modules/` – downloaded packages, huge, recreated anytime with `npm install`
  - `dist/` – webpack output, generated by `npx webpack`
- Rule: commit what I write, don't commit what can be generated.
- Clone, then open the project folder in VS Code:
  ```
  git clone <repo-url>
  cd restaurant-page
  code .
  ```
- Always check the terminal path before running npm commands (must be `...\restaurant-page>`).

## 2. package.json

```
npm init -y --init-type=module
```

- `npm init` creates `package.json` (the project's "shopping list": name, dependencies, scripts).
- `-y` accepts all default answers (can be edited in the file later).
- `--init-type=module` adds `"type": "module"` so I can use `import` / `export` (also in `webpack.config.js`).
- `scripts` = shortcuts for commands (`npm run <name>`).

## 3. Installing packages

```
npm install --save-dev webpack webpack-cli webpack-dev-server html-webpack-plugin style-loader css-loader
```

- `--save-dev` puts them in `devDependencies` – tools only for development/build, not shipped to the browser.
- Creates `node_modules/` (never commit) and `package-lock.json` (commit – exact installed versions).
- `^5.6.0` in package.json = newer versions allowed as long as the first number stays the same.
- Hundreds of packages get installed because my packages depend on other packages.

| Package             | What it does                                                         |
| ------------------- | -------------------------------------------------------------------- |
| webpack             | bundles JS modules, CSS, images into `dist/`                         |
| webpack-cli         | lets me run webpack from the terminal (`npx webpack`)                |
| webpack-dev-server  | local server at `localhost:8080`, auto-refresh on save               |
| html-webpack-plugin | builds `dist/index.html` from my template and injects the `<script>` |
| css-loader          | lets webpack understand `import "./styles.css"`                      |
| style-loader        | injects that CSS into the page as a `<style>` tag                    |

- Skipped `html-loader` – only needed for images referenced in HTML; I add images via JS.
- Before committing, `git status` must NOT show `node_modules/`.
- Commit after every finished step.

## 4. webpack.config.js

- File in project root, uses `import`/`export` thanks to `"type": "module"`.
- `import path from "node:path"` – built-in Node module for file paths.
- `export default { ... }` – the config object webpack reads.

| Option                                | Meaning                                                                                            |
| ------------------------------------- | -------------------------------------------------------------------------------------------------- |
| `mode: "development"`                 | readable output, fast build                                                                        |
| `entry: "./src/index.js"`             | starting point – webpack follows all imports from here (dependency graph)                          |
| `output.filename` / `output.path`     | result goes to `dist/main.js`; `path.resolve(import.meta.dirname, "dist")` = absolute path         |
| `output.clean: true`                  | empties `dist` before every build                                                                  |
| `devtool: "eval-source-map"`          | errors in browser console point to my original files/lines                                         |
| `devServer.watchFiles`                | dev server also reloads on `template.html` changes (it doesn't by default)                         |
| `new HtmlWebpackPlugin({ template })` | builds `dist/index.html` from my template and injects `<script>` – don't add a script tag myself   |
| `module.rules`                        | what to do with non-JS files; `test` = regex for file extension                                    |
| CSS rule                              | `use: ["style-loader", "css-loader"]` – loaders run right to left, `css-loader` must be last       |
| Image rule                            | `type: "asset/resource"` – images imported in JS get copied to `dist`, import gives the final path |

- `HtmlWebpackPlugin` is a class → needs `new`.
- After changing the config, restart `npx webpack serve` (Ctrl+C, run again).

## 5. src files + dev server

- PowerShell has no `touch`. Create files/folders with:
  ```
  mkdir src
  New-Item src/index.js, src/template.html, src/styles.css
  ```
  (`ni` = short alias for `New-Item`; errors if the file already exists – harmless)
- `template.html`: `<header>` → `<nav>` → `<button>`s (not links – JS swaps content on one page), then empty `<div id="content">`.
- Do NOT put `<script>` (HtmlWebpackPlugin injects it) or `<link rel="stylesheet">` (CSS comes via JS import) in the template.
- `index.js` must `import "./styles.css";` – webpack only knows files reachable through imports from `entry` (side-effect import).
- Run dev server:
  ```
  npx webpack serve
  ```
  → http://localhost:8080, auto-reload on save. Builds in memory – does NOT create `dist/`.
- Server blocks the terminal → open a second terminal (+) for git. Stop server with Ctrl+C.
- Console output: browser F12 → Console.

## 6. Homepage hard-coded in HTML

- Write homepage content inside `<div id="content">` in `template.html` first – easier to design layout and CSS before moving it to JS.
- Use classes for styling (`class="..."`) – later set in JS with `classList.add()`, CSS stays the same.
- Local images in HTML (`<img src="./images/x.jpg">`) need `html-loader` – I skipped it, so images will be added via JS import instead.
- Images go to `src/images/`. Free photos: Unsplash, Pexels (credit the author).
